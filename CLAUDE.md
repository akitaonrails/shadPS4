# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

shadPS4 is a PlayStation 4 emulator written in C++23, targeting Windows, Linux, and macOS (15.4+). This repository is the **emulator core only** — it has no GUI. The user-facing QtLauncher is maintained in a separate repo (`shadps4-emu/shadps4-qtlauncher`). The produced binary is a CLI: `shadps4 [flags] <CUSA id | path/to/eboot>`.

## Build, test, lint

Clang 18+ is the supported compiler; CI builds and clang-format rules all assume Clang. GCC builds are tolerated but please verify with Clang before opening a PR.

The project uses git submodules for dependencies — always clone/fetch with `--recursive` (or `git submodule update --init --recursive`).

```bash
# Configure (Linux/macOS)
cmake -S . -B build -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
# Common build types: Debug, Release, RelWithDebInfo
cmake --build build --parallel $(nproc)

# Run
./build/shadps4 --help

# Tests (opt-in — not built by default)
cmake -S . -B build -DENABLE_TESTS=ON -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
cmake --build build --parallel $(nproc)
ctest --test-dir build --output-on-failure
# Single test executable / single case:
./build/tests/shadps4_gcn_test --gtest_filter=<Suite>.<Case>
./build/tests/shadps4_settings_test
```

There are CMake presets (`x64-Clang-Debug`, `x64-Clang-Release`, `x64-Clang-RelWithDebInfo`) used by VS/VSCode — prefer these when configuring from an IDE. `-march=x86-64-v3` is forced on x86_64 builds.

**Formatting:** `clang-format-19` is authoritative (CI uses exactly v19). A `clang-format` CMake target is generated when `clang-format` is discovered. `.ci/clang-format.sh` also fails on trailing whitespace anywhere in `src/`, yml/txt/md files, `.ci*`, and `dist/`.

## Code style (from CONTRIBUTING.md)

- 100-column lines, 4-space indent, never tabs.
- Functions/classes/namespaces: `PascalCase`. Variables: `lower_case_underscored`, globals prefixed `g_`. Files/dirs: `lower_case_underscored`.
- Include order within a file: `<std>`, then third-party (`<nihstro/...>`, etc.), then project includes grouped by module, each group sorted lexicographically.
- No C-style casts — use `static_cast`/`reinterpret_cast`. Avoid `dynamic_cast`. Never `const_cast` except for const-incorrect external APIs.
- Doc comments: `///` for one-liners, `/** ... */` for multi-line (text starts on the second line). Place doc comments at the declaration, not the implementation.
- **Core must stay dependency-free and platform-agnostic**: do not add new external dependencies to `src/core`, and do not put platform-specific `#ifdef`s in Core — platform-specific shims live in `src/common/` (e.g. `signal_context.*`, `ntapi.*`, `native_clock.*`).

## Architecture

Top-level entrypoint is `src/main.cpp` (CLI11 argument parsing) → constructs `Core::Emulator` (`src/emulator.{h,cpp}`), which owns the MemoryManager, Linker, SDL window, and controllers, then calls `Run(eboot)`.

The codebase is organized into five major modules under `src/`:

### `common/`
Cross-cutting utilities with no knowledge of PS4 semantics: logging (`logging/`), path handling, assert/error, IO, threading primitives (`spin_lock`, `adaptive_mutex`, `polyfill_thread`), native clock, config loader (TOML), hashing, key management. Platform-specific code lives here (e.g. `ntapi.*`, `signal_context.*`).

### `core/` — PS4 OS / HLE runtime
- `loader/` — ELF/PRX loading and symbol resolution (`symbols_resolver.*`), plus DWARF parsing.
- `linker.{h,cpp}` — dynamic linking of PS4 modules, calls into HLE symbol tables registered by `libraries/`.
- `memory.*`, `address_space.*`, `tls.*`, `cpu_patches.*`, `signals.*` — PS4 virtual memory layout, TLS, and signal-based page-fault handling used by the GPU memory tracker.
- `file_sys/` — virtual filesystem (mount points, devices, directories); `file_format/` — PS4 container formats (PFS, PSF, TRP, PlayGo, NPBind).
- `libraries/` — **the HLE surface**. Each subdirectory implements one PS4 system module (e.g. `kernel/`, `gnmdriver/`, `videoout/`, `audio/`, `pad/`, `ngs2/`, `save_data/`, `np/`, `libc_internal/`, `ajm/`, `videodec/`). `libs.{h,cpp}` wires them into the symbol resolver. When adding a stub or fixing a syscall, this is almost always where you work.
- `devtools/` — in-emulator developer UI pieces; `debugger.*`, `debug_state.*` — gdb-stub / runtime introspection.

### `shader_recompiler/` — GCN → SPIR-V
Takes raw PS4 GCN shader bytecode and emits SPIR-V that the Vulkan backend consumes. Pipeline:
1. **`frontend/`** — decode GCN (`decode.*`, `instruction.*`, `opcodes.h`), build a CFG (`control_flow_graph.*`), translate instructions to IR (`translate/{scalar_*,vector_*,data_share,export,vector_interpolation,vector_memory}.cpp`), then recover structured control flow (`structured_control_flow.*`). Also handles fetch shaders and copy shaders (`fetch_shader.*`, `copy_shader.*`).
2. **`ir/`** — SSA IR. `program.*` / `basic_block.*` / `value.*` / `ir_emitter.*` / `opcodes.inc`. Optimization passes live in `ir/passes/` (SSA rewrite, constant propagation, identity removal, dead-code elimination, shader-info collection, etc.).
3. **`backend/spirv/`** — emit SPIR-V via the `sirit` library. `emit_spirv.{cpp,h}` is the dispatcher; per-category emitters handle integer/float/image/convert/warp/logical/atomic/etc.

`recompiler.{h,cpp}` is the top-level driver that runs the full pipeline given a `RuntimeInfo` + raw code; `profile.h` / `specialization.h` / `runtime_info.h` / `info.h` / `resource.h` / `params.h` / `bindings.h` describe what the backend needs from the Vulkan side.

### `video_core/` — GPU emulation + Vulkan renderer
- `amdgpu/` — models the PS4's "Liverpool" GPU. `liverpool.{cpp,h}` runs the PM4 command-buffer processor; `pm4_cmds.h`/`pm4_opcodes.h` decode packets; `regs*.h` mirror GPU register state; `tiling.*` handles GPU texture tiling; `pixel_format.*` maps AMDGPU formats.
- `renderer_vulkan/` — Vulkan 1.3 backend. `vk_instance.*` / `vk_scheduler.*` / `vk_master_semaphore.*` / `vk_swapchain.*` / `vk_presenter.*` are the Vulkan substrate. `vk_rasterizer.*` translates Liverpool draw state into Vulkan draws. `vk_pipeline_cache.*` + `vk_{graphics,compute,pipeline_common}.*` build pipelines from shader-recompiler output. `liverpool_to_vk.*` converts AMDGPU enums to VkEnums. `vk_shader_hle.*` provides hand-written replacements for some PS4 shaders. `host_passes/` are emulator-internal render passes.
- `texture_cache/` and `buffer_cache/` — track GPU memory residency vs guest memory, handle invalidation via the page-fault-based `page_manager.*` / `fault_manager.*`. `tile_manager.*` un-tiles textures. Host compatibility and conversion helpers live here.
- `host_shaders/` — GLSL/SPIR-V host-side shaders (blit, post-processing, present).
- `renderdoc.*` — optional RenderDoc hook; `F12` triggers a capture if RenderDoc is attached.

### `input/`, `imgui/`, `sdl_window.*`
SDL3-based window and input (controllers, keyboard/mouse mapped to DualShock). `imgui/` provides the in-emulator debug/devtools overlay and the "Big Picture" launcher mode. Keyboard/controller mappings are documented in `README.md`.

### `tests/`
Only two test binaries: `shadps4_settings_test` (TOML round-trip for emulator config) and `shadps4_gcn_test` (end-to-end GCN → IR → SPIR-V via `tests/gcn/gcn_test_runner.*`, with handwritten GCN instruction cases in `tests/gcn/test_gcn_instructions.cpp`). Both use GoogleTest (fetched via FetchContent) and link against stubs in `tests/stubs/` that replace runtime-heavy dependencies.

## Working on HLE libraries

When a game calls an unimplemented function you'll see a linker error in the log. The fix usually means:
1. Find (or create) the matching subdirectory under `src/core/libraries/`.
2. Add the function to the library's `.cpp` and register it in that library's `RegisterLib()` inside a `LIB_FUNCTION(...)` macro — matching the NID (11-char hash) of the real PS4 symbol. Look at existing entries for the exact macro form.
3. Return the appropriate `Orbis` error code (`core/libraries/error_codes.h`, `core/libraries/kernel/orbis_error.h`) rather than faking success.

## Debugging knobs

Runtime config lives in `user/config.toml` (created on first run). Useful flags when debugging:

- `[Log] filter = "Render=warning,Lib.Pad=critical"` — per-class log levels.
- `[GPU] dumpShaders = true` — dumps recompiler input/output to `user/shader/dumps`.
- `[GPU] nullGpu = true` — disables rendering (isolate CPU/HLE issues).
- `[Vulkan] validation = true`, `rdocEnable = true`, `rdocMarkersEnable = true`.

In-emulator hotkeys: `F10` FPS, `Ctrl+F10` GPU debug overlay, `F11` fullscreen, `F12` RenderDoc capture (falls back to screenshot), `Alt+F12` HUD-inclusive screenshot.

On Linux, RenderDoc requires `SDL_VIDEODRIVER=x11` — it does not work under Wayland.

## Firmware modules

A handful of official PS4 `.sprx` modules (listed in `README.md`) can be loaded via LLE from a `sys_modules/` folder. These must be user-dumped from a legally owned console and are not bundled. When a game needs one that shadPS4 doesn't HLE, point the user at that list rather than trying to reimplement it ad-hoc.
